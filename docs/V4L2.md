# Linux V4L2 backend

Enable V4L2 without RGB conversion or MJPEG decoding:

```toml
camera = { version = "0.4", default-features = false, features = ["backend-v4l2"] }
```

```rust
use camera::{
    BackendId, BackendPolicy, CameraSystem, CaptureRequest, DeviceSelector,
    SubscriptionOptions, V4l2Options,
};

# async fn run() -> camera::CameraResult<()> {
let system = CameraSystem::builder()
    .backend_policy(BackendPolicy::Require(BackendId::V4L2))
    .backend_options(V4l2Options::default().mmap_buffers(4))
    .build()?;
let mut device = system.open(DeviceSelector::Default).await?;
let session = device.start(CaptureRequest::builder().build()?).await?;
let mut frames = session.subscribe(SubscriptionOptions::latest())?;
let frame = frames.next().await?;
println!("{:?}", frame.layout());
session.close().await
# }
```

V4L2 uses streaming MMAP queues and can represent packed, multi-planar and encoded native frames. `V4l2Options::mmap_buffers` configures the driver queue independently of the library `MemoryBudget`. The backend reports actual negotiated mode and actual allocated driver buffers; unsupported counts or non-V4L2 use are errors.

`backend-v4l2` does not enable TurboJPEG. MJPEG can be relayed as native bytes without `decode-mjpeg`. Add `convert-rgb` for YUV/RGB conversion and `decode-mjpeg` only when a consumer must decode MJPEG.

Device indices are enumeration positions. Persist `DeviceId` only after checking `IdentityStability`; by-id or serial-backed identities are preferred, while `/dev/videoN` may be enumeration-only. Permission denial, device busy, unsupported target and absent compile-time backend are distinct errors.

Native means format-preserving, not zero-copy: dequeued driver planes are copied into the bounded immutable frame pool before the V4L2 buffers are requeued. Retaining a frame therefore cannot corrupt later capture, while pool pressure can drop incoming frames and is visible in metrics/events.
