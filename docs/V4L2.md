# V4L2 backend

The Linux default `native` feature selects V4L2. Android can explicitly enable
`backend-v4l2`; when Camera2 is enabled, Android's default remains Camera2.
The backend uses kernel V4L2 MMAP queues and does not require libv4l2 or USB detachment.

```rust,no_run
use camera::{BackendType, CameraSystem, StreamRequest};
use std::time::Duration;
# async fn example() -> camera::CameraResult<()> {
let system = CameraSystem::with_backend(BackendType::V4l2);
let device = system.devices().await?.into_iter().next().unwrap();
let mut camera = system.open(&device.id).await?;
let session = camera.start(StreamRequest::builder()
    .resolution(640, 480).driver_buffers(4).build()?).await?;
let mut frames = session.subscribe();
let frame = frames.next_timeout(Duration::from_secs(3)).await?;
println!("{:?}: {:?}", session.negotiated_config(), frame.layout());
session.stop().await?;
# Ok(())
# }
```

Use the returned `DeviceId`, preferably backed by `/dev/v4l/by-id` or
`/dev/v4l/by-path`, rather than storing enumeration indices. The diagnostic
`backend_probe --device /dev/videoN` selects a reported native ID.

Supported capture formats include MJPEG, YUYV, UYVY, RGB24, GREY, NV12 and
NV12M; `OutputFormat::Native` preserves source bytes and plane/stride metadata,
while `Rgb8` converts through the bounded shared pool. Fractional frame rates
are represented as rational numbers. Continuous/stepwise capabilities expose
representative samples; `SelectionPolicy::Exact` may try an unlisted mode and
rejects driver changes. Controls expose queried ranges, writability and native
units; mode and numeric controls are separate.

The capture worker validates bytesused, plane offsets, row lengths and buffer
indices. A socket wakes poll during stop. Resource release proceeds through
STREAMOFF, munmap and REQBUFS(0). Native driver buffers (2–32) and the application
frame pool have separate budgets. Slow receivers discard queued frames without
overwriting retained frames.

Enumeration skips unsupported nodes. If all usable nodes are inaccessible,
`CameraError::PermissionDenied` explains the access requirement. On standard
Linux, use the system's video group or udev policy. On Android, CAMERA permission
does **not** grant `/dev/videoN` access: use Camera2 or an authorized UsbManager
connection for normal applications. V4L2 requires a suitably privileged process
or platform policy. The library does not chmod device nodes or invoke root.

A CSI/ISP node may require platform media graph configuration before capture.
USERPTR/DMABUF, media-controller setup, interlaced video and H264 decoding are
outside this backend's current support.

```sh
cargo run --release --example backend_probe -- --backend v4l2 --list
cargo run --release --example backend_probe -- \
  --backend v4l2 --device /dev/video0 --frames 120 --rounds 5
./scripts/test-native.sh
```
